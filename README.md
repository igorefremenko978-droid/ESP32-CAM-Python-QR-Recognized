## Что это

Комплексный проект из двух взаимодействующих частей, решающий одну задачу: распознавание QR-кодов с камеры ESP32-CAM и отображение результатов на компьютере.

| Часть | Технологии | Роль |
|-------|------------|------|
| Прошивка ESP32-CAM (`ESP-CAM.ino`) | Arduino C++, esp32cam, WebServer, Preferences | Камера + HTTP-сервер: захват кадров, управление подсветкой, настройки камеры, веб-интерфейс |
| Десктоп-приложение (`main.py` + `core/` + `ui/`) | Python, PyQt6, OpenCV, pyzbar, requests | GUI-клиент: запрос кадров, распознавание QR, лог, ручной/авто-режимы |



## Как они объединяются

Связующим звеном является HTTP-протокол и класс `CameraClient` на стороне Python:

```text
┌─────────────────────────┐         HTTP          ┌──────────────────────────┐
│   ESP32-CAM (прошивка)  │ ◄───────────────────► │  Python-приложение       │
│                         │                       │                          │
│  GET /         (ping)   │                       │  CameraClient            │
│  GET /capture  (JPEG)   │                       │   ├─ check_connection()  │
│  GET /led      (управл.)│                       │   ├─ capture_frame()     │
│  GET/POST /settings     │                       │   └─ set_led()           │
│                         │                       │  QRProcessor             │
│  Веб-интерфейс (браузер)│                       │   └─ process_frame()     │
└─────────────────────────┘                       └──────────────────────────┘
```

Прошивка — это «сервер», который умеет отдавать кадр, включать/выключать подсветку и хранить настройки камеры в NVS. Python-приложение — это «клиент», который дёргает эти эндпоинты, декодирует JPEG, ищет QR через pyzbar, рисует рамки и ведёт лог.

## Ключевые возможности (сводно)

### Со стороны камеры

- HTTP-сервер на порту 80;
- эндпоинт `/capture` для получения JPEG-кадра;
- эндпоинт `/led` для оперативного управления подсветкой (без записи в NVS);
- веб-настройки камеры (разрешение, JPEG-качество, яркость/контраст/насыщенность сенсора, баланс белого) с сохранением в NVS;
- мультисетевое подключение к Wi-Fi (до 10 сохранённых сетей) с выбором рабочей сети при загрузке;
- режим точки доступа (AP) для первичной настройки, вход в него — удержание кнопки BOOT 3 секунды.

### Со стороны приложения

- захват кадра по кнопке или по таймеру;
- распознавание всех QR-кодов на кадре за один снимок;
- ориентация QR не важна — pyzbar декодирует коды в любом положении;
- отображение кадра с рамками вокруг найденных кодов;
- управление подсветкой с регулировкой яркости;
- ручной и автоматический режимы (интервал 1–60 с);
- лог с отметками времени и копированием как отдельных строк, так и всего лога целиком;
- диалог настроек подключения (IP + порт) с проверкой доступности камеры.

## Особенности интеграции

- **Разделение ответственности:** камера отвечает только за «железо» и сеть, Python — только за UI и распознавание. Это позволяет независимо перепрошивать камеру и обновлять приложение.
- **Оперативность подсветки:** состояние LED намеренно не пишется в NVS — это временный параметр, который сбрасывается при перезагрузке. NVS используется только для настроек камеры и Wi-Fi.
- **Устойчивость к сбоям:** сетевые запросы имеют таймаут 5 с; при недоступной камере приложение пишет ошибку в лог и продолжает работу.
- **Кроссплатформенность клиента:** Python-часть работает на Windows/Linux/macOS; прошивка привязана к ESP32-CAM (AiThinker).

## Итог

Проект представляет собой законченную систему «умная камера + десктопный сканер»: ESP32-CAM выступает в роли сетевой камеры с управляемой подсветкой и веб-настройками, а Python-приложение — в роли удобного рабочего места оператора с распознаванием QR, логом и двумя режимами съёмки. Обе части связаны простым и предсказуемым HTTP API, что делает систему расширяемой и удобной для отладки.
